# Эксплуатация

## Одно получение обновлений на бота

Используйте отдельный Telegram-бот без webhook. Программа проверяет webhook,
но не удаляет его автоматически. Redis lease90с и fenced cursor позволяют
перезапустить экземпляр; если старый процесс аварийно завершился, другой
может ждать до90с плюс один цикл long polling. Это не active-active кластер.

Long polling20с, ответ ограничен1МиБ. При ошибке обновления пишется только
нейтральный код и курсор идёт дальше: ручную неудачную команду нужно повторить.
Если Redis недоступен, запросы доступа/отправки не должны выполняться в обход него.
Встроенный health проверяет polling, а не наличие свежих бизнес-данных.

## Отчёты и напоминания

Ежедневный отчёт за вчера доставляется один раз за локальный день после выбранного
часа. Включение начинает доставку со следующего дня. После простоя догоняется только
текущий выпуск, без очереди пропущенных дней. Один и тот же выпуск не повторяется
после рестарта или изменения часа. Ручные отчёты не меняют ежедневный период.

Финансовый скан не чаще5мин, независимо от подписки на отчёт. Только статическим
владельцам из `OWNER_IDS`,09:00–20:59 `TIMEZONE`:

- Остатка хватает на `LOW_BALANCE_DAYS` или меньше: повтор через24ч со свежими
  данными. Выше порога/unknown — тишина. Сам баланс может быть большим: критерий — дни.
- Домен: этапы30/7/3/1 и отдельный этап0 при истечении. Дни календарные в `TIMEZONE`.
  Если пропущен этап, приходит только актуальный, например при6 днях — этап7.
  На домен/дату/этап/владельца одно сообщение; новый срок начинает новый цикл.

До отправки создаётся Redis NX claim. Timeout может означать, что Telegram уже
принял сообщение, поэтому claim сохраняется: возможен пропуск одного выпуска,
зато повтор не рассылается. Явный429 повторяется по ограниченному Retry-After;
400/401/403 — через сутки, прочий явный отказ — через60с. Это не гарантия
exactly-once доставки. Ежедневные claims живут3суток, финансовые24ч, доменные400дней.

## Настройки доступа

Владелец хранится только в env, зрители не могут назначить владельца. До50 зрителей
и100 заявок; заявка живёт7дней, отклонённая — сутки. Callback содержит случайный
nonce; старое одобрение не восстанавливает отозванный доступ. Полная сводка,
включая остатки, доступна всем одобренным зрителям — выдавайте доступ осознанно.

Имя и Telegram ID нужны для администрирования и сохраняются в Redis. Для удаления
данных человека после отзыва удалите его записи штатным кодом или административной
процедурой своего развёртывания; не отправляйте дампы Redis в публичные issues.
Передавайте изменённый список владельцев через env и пересоздание контейнера.

## Что нужно проверить у себя

- Источник считает UTC-периоды и All-регистрации по одним правилам с вашим дашбордом.
- Обновляются оплаченные сроки доменов и текущие остатки, `null` не подменяется нулём.
- Время сервера синхронизировано, Redis AOF и backup работают.
- Бот не запущен параллельно с другим getUpdates/webhook сервисом.
- `/start`, approval/revoke, ручная карточка, daily и напоминания проверены на ваших
  данных и отдельном тестовом боте перед выдачей доступа клиентам.

Шаблон не оплачивает услуги, не продлевает домены, не начисляет баланс и не служит
внешним uptime-монитором собственного сервера.
